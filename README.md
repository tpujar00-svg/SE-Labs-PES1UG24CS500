# Lab 1 – Requirements Engineering & UML Use-Case Modelling

## Course
Software Engineering

## Lab Objective
The objective of Lab 1 is to elicit and document software requirements from an assigned scenario and model the system using UML use-case modelling.

## Assigned Scenario
**Statement 12 – Blood Bank Inventory & Emergency Donor Matcher**

The system focuses on managing blood-bank inventory and supporting emergency donor matching. It involves real-time inventory management, monitoring blood-component shelf life, and notifying compatible eligible donors during critical shortages.

## Lab 1 Deliverables

### 1. Requirements Table
The requirements table contains:
- 5 Functional Requirements (FRs)
- 2 Non-Functional Requirements (NFRs)
- Requirement ID
- Requirement Type
- Description
- Priority
- Acceptance Criteria
- Rationale

### 2. UML Use-Case Diagram
The UML diagram includes:
- System boundary
- Actors
- Use cases
- Associations
- At least one `<<include>>` or `<<extend>>` relationship

### 3. Use-Case Flow
The use-case flow contains:
- Main Success Scenario
- Alternate Flow
- Preconditions
- Postconditions
